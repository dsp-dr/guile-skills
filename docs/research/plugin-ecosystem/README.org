* Checked here before recommending

- =relevance= is a real, strictly validated marketplace field, but its shape is
  ={topic, signals: {filesRead, cli, hosts, manifestDeps}}=. Putting =cli= at the
  top level is rejected ("Unknown field 'cli'"), and so is a misspelled signal
  ("did you mean 'filesRead'?"). Our entry,
  ={"topic":"Guile","signals":{"filesRead":["**/*.scm","**/*.sld"],"cli":["guile","guile3","guile-3.0","guild"]}}=,
  passes =--strict= on a full copy of the tree. *measured*, CLI 2.1.287.
- =marketplace.json= =metadata.version= is 1.0.0 while =plugin.json= is 0.4.1.
  *measured*.
- *Contract drift:* on 2.1.287, =validate= checks that =experimental.monitors=
  points at a file that exists. =contracts/artifacts.json= records monitors as
  wholly unvalidated, as measured on 2.1.261. Re-measure before the pin moves.
  *measured*.

* Considered, not now

- *Collapse to =setup= + =eval=.* Supported by how others split skills: by user
  intent or with an entry skill, never by component the way ours are. But #1
  might fix triggering without breaking anyone. If it lifts the failing
  prompts, the merge becomes a maintenance choice; if not, it is the next
  experiment. Breaking either way.
- *Rename the marketplace to the owner* (=guile@dsp-dr=). 22 of 35 catalogues
  name it after the owner, and none after the plugin. But there is no
  marketplace-level rename, so every install id changes. It belongs with the
  next breaking change, done once, with the old catalogue left in place as a
  pointer.
- *Paren repair* (clojure-mcp-light repairs with parinfer and backs up before the
  edit). Ours detects only. Repair writes the user's files, which crosses a
  boundary our hook keeps; worth an experiment, not a default.
- *Agent frontmatter* (=model=, =effort=, =maxTurns=, a restricted =Agent(...)=).
  Pinning a model changes users' cost. Worth it for =geiser-setup='s turn limit
  alone.

* Confirmed decisions

- *No MCP server.* clojure-mcp (779 stars) now steers Claude Code users to a hook
  plus a CLI rather than MCP.
- *No =commands/=.* It is documented as legacy in favour of skills.
- *LSP inline, if ever.* The official LSP plugins declare servers in
  =marketplace.json= with =strict: false= and ship no =.lsp.json=, which matches
  our finding that =.lsp.json= is never read.
- *The directory is unobserved everywhere.* No repo found records a publish as
  a GitHub Deployment or reports directory state back. Our R6 gap is the
  ecosystem's gap, not a local oversight.
