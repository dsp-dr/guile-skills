#+TITLE: Boundaries: the layers of REPL-driven development
#+DATE: 2026-09-29
#+AUTHOR: dsp-dr

Interactive development here has more moving parts than it looks: a human in
Emacs, an agent in a session, two Guile processes, a transcript, and a plugin that
has to reach all of it without reaching anything else. Most of the failures in
this repository are boundary failures --- something crossed a line it should not
have, or failed to cross one it should have.

This file draws the lines and says who may cross each.

* The layers

* The workflow that keeps it honest

Development boundaries are only real if crossing one is *noticed*. Four
mechanisms, in the order they fire:

1. =gmake dx= --- the session where work happens: editor, REPL, validators on a
   loop, shell. The harness re-runs the metadata checks on every save, so a
   boundary broken in a =SKILL.md= or a manifest is caught seconds later rather
   than in CI.
2. =gmake checks= --- the local gate: lint, generated-doc sync, script drift,
   version bump, frontmatter, eval suites, monitor entries, proxy regressions.
3. =scripts/check-version-bump.sh= --- answers one question: did this change cross
   the shipped boundary, and if so did =version= move? It reads the *working
   tree*, and it now also looks at untracked files, because a brand-new shipped
   component was previously invisible to it.
4. =gmake wip= --- answers the other question: is anything held only on this
   machine? Uncommitted changes, unpushed branches, a notes ref ahead of origin,
   =notes.rewrite*= unset, and per commit its file list and whether it carries a
   note.

The last one exists because the failure mode is not forgetting to commit; it is
committing *part* of the work and pushing a message that describes the rest.

* What is deliberately not a boundary

- *The debugger is not a separate channel.* =,bt=, =,trace=, =,break= travel the
  same socket as ordinary evaluation, which is why one proxy records both.
- *The agent is not privileged over the human.* Both connect to the proxy, both
  appear in the same transcript, and the transcript is the shared record.
- *Nothing here is a reservation.* A derived port is a convention; two projects
  can still collide, and the only correct response is to check what is listening.
