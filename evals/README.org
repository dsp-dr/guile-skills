#+TITLE: Evals
#+DATE: 2026-09-26

Five cases, each targeting one anti-pattern this plugin exists to prevent. Run
them with:

#+begin_src sh
claude plugin eval . --allow-tools Bash --scaffold --no-publish --max-cost-usd 15
#+end_src

=--scaffold= lets =no-linter-claim= copy its fixture into the run's empty
directory. =--no-publish= keeps the HTML report local. With-without ablation is
the default whenever the plugin resolves.

* Status: loads, *not yet scored*

=claude plugin eval= is available from CLI 2.1.286 (issue #20 had it gated at
2.1.261). Measured on 2026-10-01:

- *As first written, no case loaded.* Every grader was plain prose, and the CLI
  requires frontmatter with a =type:= (=invalid case.yaml: graders: Required=).
  The suite had never been run, so nothing had noticed.
- *Now all five load and parse as intended*, checked against the real loader at
  $0 (see below): =focus: trace= on the graders that ask "did it run?",
  =with-only= on the plugin-fired indicators, weights as written.
- *No case has been scored.* Every case needs Bash, and a Bash-granting run on the
  maintainer's macOS laptop is refused before it starts. The sandbox reports that
  "the Docker (~/.docker) credential store ... holds a symbolic link inside it, so
  the Bash sandbox cannot reliably exclude it". Docker Desktop creates those
  links. The refusal protects credentials, so it is not worked around here. A
  host with no symlinks in =~/.docker=, or a Linux runner with =bubblewrap= and
  =socat=, can run the suite.

The free load check: grant Bash on a host where the sandbox refuses. Every case
is loaded and parsed, then every run is refused at $0, and =--json= shows the
parsed graders.

Until a run exists under =evals/results/=, treat every claim about these cases as
untested. This plugin's argument is that unverified claims are the failure mode,
and an eval suite nobody has run is that failure in miniature.

Tier 1 runs here today:

#+begin_src sh
claude plugin eval . --tag tier1 --scaffold --trust-plugin --no-publish --max-cost-usd 5
#+end_src

=trigger-resume= ("I'm resuming work on this Guile project, get me set up"), 3
runs per arm: the setup skill fired 3/3 with the plugin and 0/3 without, for
$0.92 in 165 s. Each arm runs *isolated*: no other skills, no CLAUDE.md, no
installed plugins. So a tier-1 rate is the plugin's trigger rate *alone*. The
trigger benchmark (=evals/trigger/run.py=) measures it among a real user's ~80
competing skills. The gap between the two is the cost of that competition,
which is the comparison that explains the misses in EXPERIMENTS-invocation.

Tier 2 needs a host where the Bash sandbox will run. Choose one:

1. A Linux runner with =bubblewrap= and =socat=, an API-key secret (the owner's
   call) and a cost cap, as coalesce-labs/catalyst-cloud-skills does
   (docs/research/plugin-ecosystem/ci-release-evals.org). An ephemeral runner
   also makes =stale-listener='s process killing safe.
2. A machine whose =~/.docker= holds no symbolic links.
3. Pointing =DOCKER_CONFIG= elsewhere for the run. *Not done*: that sidesteps a
   guard protecting credentials, and only the owner should choose it.

* Form

Each case is a directory holding =prompt.md= (frontmatter: =name=, =tags=,
=runs=, =max_turns=, =timeout_seconds=, =allowed_tools=; then the prompt) and
=graders/*.md=. Each grader needs frontmatter with =type:= (=llm=, =tool_used=, and
others). An =llm= grader judges =last_message= unless it sets =focus: trace=, so
any grader asking whether something was *run* must set it.
=no-linter-claim= adds a =case.yaml= for its =scaffold_script=. Every run starts
in an empty directory, and the script copies =scripts/lib/guile-repl-proxy.scm=
in.

Graders are written to be *host-neutral*. The interpreter is =guile3=,
=guile-3.0= or =guile= depending on the platform, and a bare =guile= can be 2.x,
so they judge the behaviour (ran it, named the binary, checked it is 3.x), not
one machine's names. They were first written for nexus, where only =guile3= is
3.x, and would have failed a correct run on Homebrew.

=stale-listener= is tagged =kills-processes=. Its baseline arm may reasonably
=pkill= a REPL, so run it only where no one else's REPL is live:
=--tag= filters, and the sandbox's process rules are not established.

* Why the ablation matters

~--ablation with-without~ runs each case twice, with the plugin and without, and
reports the delta. A skill that scores well in both arms did nothing. Graders
marked ~with-only~ (including ~tool_used: Skill~) are plugin-fired indicators
rather than part of the score.
